# 个人 AI 知识系统设计规格

- 日期：2026-07-29
- 工作名称：Recall AI（仅作为内部工作名称，产品命名不影响本规格）
- 目标用户：首版仅供系统所有者个人使用，数据模型预留多用户隔离
- 产品形态：响应式 Web 应用 + Chrome/Edge 浏览器扩展
- 状态：设计已逐章确认，等待书面规格复核

## 1. 背景与问题

用户长期在 Codex、ChatGPT、Claude、豆包、WorkBuddy、小红书等产品中获取 AI 相关答案和资料。内容通常在当时被理解和记住，却没有形成可持续的沉淀；数月后遇到相似问题时，既难以回忆，也难以重新找到原始答案，只能再次消耗时间、额度和精力查询。

系统需要解决三个连续问题：

1. 重要内容能低摩擦地进入系统，并明确告知采集是否成功。
2. 数月后可以通过模糊描述、中英文术语或少量错别字找回旧内容。
3. 零散问答和资料逐步形成可编辑、可追溯、可复用的知识卡片、主题关联和成长回顾。

首版还需支持轻量研究专题，使用户能围绕竞品或 AI 主题持续加入资料，并生成带来源引用的对比摘要。

## 2. 产品目标

### 2.1 核心闭环

首版应完成以下闭环：

> 多入口采集 → 原始资料可靠保存 → AI 异步整理 → 用户快速确认 → 长期知识入库 → 混合搜索与有引用问答 → 每日/每周成长回顾

### 2.2 优先级

1. 主目标：自动或低摩擦采集。
2. 兼顾目标：AI 自动总结、拆卡、分类和关联。
3. 第一阶段内容范围：AI 对话 + 用户主动收藏的网页、帖子、文件和截图。
4. 系统成熟后再扩展：自动监控指定账号、产品、主题和竞品动态。

### 2.3 成功定义

上线使用一个月后，系统应同时证明：

- 重要内容可以快速收藏，并可靠告知完整、部分或失败状态。
- 再次遇到类似问题时，可以找到过去的记录和知识卡片。
- 每周回顾能展示新增认知、重复问题、知识盲区、过时内容和下一步建议。

## 3. 首版范围

### 3.1 包含

- 响应式 Web 应用，支持电脑和手机浏览器。
- Chrome 与 Edge 共用的 Chromium 浏览器扩展。
- ChatGPT 网页版优先适配：
  - 完整会话采集。
  - 再次采集同一会话时仅追加新增消息。
  - 当前问答、选中文字的片段级收藏。
- 小红书网页版优先适配：
  - 尝试提取当前笔记标题、正文、作者、链接和可见图片。
  - 解析失败时提供截图与 OCR 兜底。
  - 不进行自动批量爬取。
- 通用入口：
  - 粘贴文本。
  - 上传文件。
  - 上传单张或多张截图。
  - 普通网页正文或选中文字收藏。
- 原始记录、原子知识卡片、主题地图三层知识结构。
- 卡片字段直接编辑、自动保存、版本恢复和人工修改保护。
- 关键词、语义、拼写容错和筛选组合的混合搜索。
- 基于个人知识库的有引用问答。
- 临时收件箱、自动分流、每日优先事项和每周邮件回顾。
- 可自动推荐、手动创建并复用的标签。
- 轻量研究专题与带引用的持续对比摘要。
- 敏感级别自动建议、人工覆盖和授权审计。
- 归档、30 天回收箱和永久删除。
- 采集失败、部分采集、处理失败的明确提示与重试。
- 成本统计、预算提醒和处理审计。
- 首版只开放个人账号，但所有业务数据带用户所有权边界。

### 3.2 暂不包含

- 原生手机 App、独立桌面 App和 Safari 扩展。
- Claude、豆包、Codex、WorkBuddy 的自动采集适配。
- 旧平台历史记录批量迁移。
- 跨外部 App 输入框的实时相似问题提醒。
- 自动关注账号、主题或竞品动态。
- 全网采集、复杂竞品评分和自动长报告。
- 公开注册、订阅收费、团队空间和协作权限。

这些能力需在首版稳定后分别进入独立的规格、计划和实现周期。

## 4. 设计原则

1. **先保存，再理解。** 采集入口只在服务器确认原始资料保存后提示成功；AI 处理可异步排队。
2. **原文是证据。** 摘要和卡片不能替代原始资料，任何生成结论均可追溯到具体来源片段。
3. **自动化可撤销。** AI 推荐的标签、专题、敏感级别、合并和结论都可被用户修改。
4. **人工修改受保护。** AI 不得静默覆盖用户确认或手工编辑的字段。
5. **失败必须可见。** 部分采集、采集失败与 AI 处理失败需分开报告。
6. **隐私默认从严。** AI 可以自动提高保护级别；降低保护或扩大处理权限需要用户确认。
7. **减少日常负担。** 系统自动处理高置信内容，只把不确定、冲突、敏感或高价值内容优先呈现。
8. **当前个人、未来隔离。** 首版不做多用户产品功能，但数据结构和访问控制不得假设全局只有一个用户。

## 5. 系统架构

采用模块化个人知识系统。首版使用托管云服务降低服务器运维负担，但各模块通过明确接口分离，以便以后替换模型、存储或任务服务。

### 5.1 逻辑组件

#### Web 应用

职责：

- 用户登录、首页、临时收件箱、搜索问答、知识卡片、主题地图、研究专题、回顾、归档、回收箱和设置。
- 文件、截图和文本上传。
- 卡片编辑、版本查看和恢复。
- 敏感授权、成本与处理审计。

依赖：

- 应用 API。
- 身份认证服务。
- 文件存储、数据库和搜索服务。

#### Chromium 浏览器扩展

职责：

- 识别当前支持的网站和页面类型。
- 采集完整会话、当前问答、选中文字、普通网页正文或当前页面截图。
- 提供研究专题、标签和敏感级别建议。
- 在服务器确认前保留待提交数据。
- 展示完整采集、部分采集、采集失败和处理状态。

依赖：

- 采集 API。
- 浏览器本地临时存储。
- 针对 ChatGPT、小红书的独立页面适配器。

#### 采集网关

职责：

- 鉴权、限流、来源识别、输入验证和附件登记。
- 生成幂等键和内容指纹。
- 按会话、页面和片段合并增量内容。
- 原始资料与元数据持久化。
- 返回可验证的采集结果。

不负责：

- 在同步请求中完成 OCR、摘要或知识拆卡。

#### 原始资料保险箱

职责：

- 保存原始文本、会话结构、网页快照、截图、附件和来源元数据。
- 支持版本、归档、回收、恢复和永久删除。
- 为后续索引和知识结构提供唯一证据来源。

#### 后台处理队列

职责：

- OCR、语言识别、文本规范化、去重、摘要、原子拆卡、标签推荐、专题推荐、敏感判断、关联发现和索引更新。
- 按任务类型选择模型并记录成本。
- 自动重试、退避、失败隔离和人工处理入口。

#### 知识与检索层

职责：

- 保存卡片、卡片版本、标签、专题、关联、冲突、引用和新鲜度状态。
- 同时提供全文搜索、语义搜索、拼写容错、结构化筛选和结果重排。
- 支持通过原始数据重建检索索引。

#### 回顾与通知

职责：

- 生成每日优先事项。
- 生成每周成长回顾。
- 发送浏览器通知和邮件摘要。
- 通知发送失败时保留可重试状态，不影响回顾本体。

### 5.2 技术边界

实施计划以以下技术类别为基准：

- TypeScript 代码库，共享 Web、扩展和数据契约类型。
- 响应式 Web 前端与服务端 API。
- Chromium Manifest V3 扩展。
- 托管关系数据库，支持向量索引或可替换的向量检索层。
- 对象存储保存截图与附件。
- 可重试的后台任务队列。
- 可替换的 AI/OCR 提供商适配层。
- 邮件服务和浏览器通知。
- 托管密钥管理，不把服务密钥写入客户端或代码仓库。

具体托管厂商和模型在实施计划中按隐私承诺、留存控制、中文能力、成本、区域可用性和替换成本选择。该选择不得改变本规格中的数据边界和接口。

## 6. 核心数据模型

所有业务实体均包含 `owner_user_id`，多用户开放前也必须执行所有权过滤和访问控制。

### 6.1 SourceItem（原始资料）

- 所有者。
- 来源类型与平台。
- 原始标题、原始内容和附件。
- 来源 URL、外部会话标识、外部消息标识。
- 采集范围：完整会话、当前问答、选中文字、网页、截图或上传。
- 内容指纹、版本和增量位置。
- 采集完整度：完整、部分、失败。
- 处理状态：待处理、处理中、完成、失败、暂停。
- 敏感级别与授权状态。
- 创建、更新、归档、删除时间。

### 6.2 KnowledgeCard（知识卡片）

- 标题。
- 核心结论。
- 适用条件和限制。
- 关键术语及中英文别名。
- 来源引用列表。
- 标签和主题。
- 关联卡片。
- 置信状态：AI 草稿、待确认、已确认。
- 新鲜度与建议复查时间。
- 人工编辑保护标记。
- 当前版本和版本历史。

### 6.3 ResearchProject（研究专题）

- 名称、目标和范围。
- 成员资料和知识卡片。
- 用户定义及 AI 建议的对比维度。
- 带引用的当前摘要。
- 核心发现、待验证问题和冲突项。
- 摘要版本和上次更新时间。

### 6.4 Tag（标签）

- 名称、标准化名称和别名。
- 创建方式：人工或 AI 推荐后确认。
- 所有者和使用次数。
- 可合并的同义标签关系。

系统优先推荐已有标签，AI 不得在没有确认的情况下批量创建新标签。

### 6.5 ProcessingJob（处理任务）

- 任务类型和关联原始资料。
- 当前状态、尝试次数和下一次重试时间。
- 使用的模型或服务、用途、输入范围、费用和留存策略快照。
- 成功结果或可理解的失败原因。

### 6.6 ConsentRecord（授权记录）

- 资料范围：单条、批量或明确规则。
- 敏感级别。
- 被授权的服务方和处理用途。
- 授权时间、撤销时间和操作者。

不提供含糊的全局永久放行。规则授权必须限定专题、来源、敏感级别、服务方或用途，并可随时撤销。

## 7. 核心流程

### 7.1 完整会话采集

1. 扩展识别平台和会话。
2. 用户选择保存完整会话。
3. 扩展生成会话标识、消息标识和内容指纹。
4. 采集网关比较已保存版本，仅接收新增或变更内容。
5. 原始资料与附件保存成功后返回确认。
6. 扩展显示“完整采集成功”及保存数量。
7. 后台任务开始 OCR、去重、摘要和拆卡。

### 7.2 片段收藏

用户可以保存当前问答、选中文字或截图。片段作为独立原始资料，同时记录其所属会话或网页。卡片引用具体片段，需要上下文时可回看完整来源。

### 7.3 小红书采集

1. 扩展尝试读取当前可见笔记的结构化内容。
2. 读取结果通过基本完整性检查。
3. 页面结构不受支持、图片缺失或正文不完整时，明确显示“部分采集”。
4. 用户可补充当前页面截图或在 Web 应用上传手机截图。
5. OCR 结果与网页内容合并，保留原截图。

系统不绕过平台访问控制，不进行后台批量抓取。

### 7.4 AI 知识处理

1. 规范化文本、识别语言和 OCR。
2. 检查重复、增量和潜在同义内容。
3. 生成摘要和原子卡片草稿。
4. 提取结论、适用条件、限制、术语和行动项。
5. 推荐已有标签、主题和研究专题。
6. 建立来源引用。
7. 按置信度和风险分流：
   - 高置信、非敏感、无冲突：自动入库。
   - 不确定、冲突、敏感或高价值：进入每日确认。
   - 低价值：归档，不直接删除。
8. 更新搜索索引、主题关联和研究专题修订建议。

### 7.5 冲突与过时

- 重复结论：合并来源并提升证据强度，不重复建卡。
- 相互冲突：保留两个结论，显示时间、来源与适用条件，不覆盖旧卡。
- 内容过时：保留历史版本并标记复查，不删除历史。
- 模型价格、上下文长度等时效性强的信息，应有较短复查周期。

### 7.6 卡片编辑

- 标题、结论、适用条件、标签等字段支持直接点击编辑。
- 自动保存并保留版本。
- 用户可撤销或恢复先前版本。
- AI 后续建议不得覆盖人工修改；需显示差异并由用户选择保留、合并或创建新版本。

### 7.7 混合搜索与知识库问答

检索并行使用：

- 全文搜索：产品名、模型名、代码、术语和精确短语。
- 语义搜索：模糊描述、同义表达和中英文概念。
- 拼写容错：少量错别字、漏字和近似名称。
- 结构化筛选：来源、时间、主题、标签和研究专题。
- 结果重排：按当前问题相关度、来源质量、新鲜度和用户确认状态排序。

问答界面同时展示相关历史记录和生成答案。生成答案必须引用个人知识库来源；若证据不足，系统明确说明，并可建议用户发起新的外部查询。

### 7.8 相似问题提醒

首版后段在系统自身的搜索/提问输入框内提示历史相似问题。跨 ChatGPT、Claude、豆包等外部输入框的实时提醒不属于首版。

## 8. 产品界面

### 8.1 全局导航

- 今天。
- 临时收件箱。
- 搜索与提问。
- 知识卡片。
- 主题地图。
- 研究专题。
- 每周回顾。
- 归档。
- 回收箱。
- 隐私、成本和数据设置。

### 8.2 今日首页

首页围绕“今天最值得处理什么”组织：

- 全局搜索与知识库提问。
- 今日采集、新增知识和重复合并统计。
- 后台处理队列与成本概览。
- 按优先级排列的每日确认事项。
- 正在进行的研究专题。
- 未恢复的采集异常。

优先级以颜色、文字和排序共同表达：

- 重要且紧急。
- 重要但不紧急。
- 紧急但一般。
- 一般事项。

优先级依据内容风险、知识价值、时间要求和历史操作自动建议，用户可修改。

### 8.3 扩展收藏面板

面板包含：

- 已识别来源。
- 保存范围。
- AI 推荐研究专题及匹配度。
- 新建或选择已有专题。
- AI 推荐已有标签、删除标签和创建可复用标签。
- 敏感级别及判断理由。
- 增量采集提示。
- 保存与后台整理操作。
- 明确的结果状态。

### 8.4 采集状态

- **完整采集成功：** 服务器已确认原始文本和预期附件保存。
- **部分采集：** 已保存可用内容，但明确列出缺失项和补救入口。
- **采集失败：** 服务器未确认保存；本地暂存并自动或手动重试。
- **原文已保存、AI 处理失败：** 明确说明资料未丢失，后台重试。

异常需持续出现在：

- 扩展角标和异常列表。
- Web 首页的重要事项。
- 自动重试仍未恢复时的浏览器通知或每日摘要。

用户处理前，异常不得因页面关闭而消失。

### 8.5 归档与回收箱

- 归档：内容仍可搜索，可恢复到主知识库。
- 回收箱：用户明确删除的内容默认保留 30 天，可恢复。
- 永久删除：清理原文、附件和对应检索索引；仅由该资料生成的卡片一并删除。若卡片同时引用其他来源或含有用户手工内容，则移除被删来源、保留卡片并重新计算其证据状态。

## 9. 研究专题

首版研究专题是轻量工作区，而非完整竞品平台。

### 9.1 能力

- 定义研究目标和范围。
- 手工或 AI 推荐加入资料与卡片。
- 用户创建对比维度，AI 可提出新维度。
- 自动生成带逐项引用的对比摘要。
- 提炼核心发现和待验证问题。
- 标记证据不足、资料冲突和可能过时的结论。
- 新资料加入后生成修订建议。

### 9.2 更新规则

- AI 不静默覆盖用户确认的研究判断。
- 修订需展示新增证据和影响范围。
- 用户选择接受、部分合并或拒绝。

## 10. 每日确认与每周回顾

### 10.1 每日确认

系统优先展示：

- 采集失败或部分采集。
- 隐私判断和授权请求。
- 冲突或低置信卡片。
- 高价值卡片。
- 即将按规则归档的低价值内容。

目标是让用户通常可在约 5 分钟内完成核心处理，但不设置时长上限。用户可以继续进入全部内容进行深度回顾。

### 10.2 每周回顾

每周邮件和 Web 完整页面至少包含：

1. 本周新增认知。
2. 重复出现的问题。
3. 当前知识盲区。
4. 可能过时、需要复查的内容。
5. 下一步建议。

同时展示本周成长主题和研究专题变化。用户可用“有用 / 一般 / 无用”反馈质量，后续回顾据此调整内容，而不是只统计数量。

## 11. 隐私与授权

### 11.1 分级

- 普通：默认允许已批准的合规 AI API。
- 敏感：默认暂停外发；只有命中用户已批准的明确规则，或获得本次明确授权后，才允许发送给不用于训练、留存可控的合规 API。
- 严格敏感：默认暂停外发；只有获得本次或范围足够明确的专项授权后，才允许发送给指定合规 API。

敏感和严格敏感内容在用户明确授权后，可以发送给指定合规 AI API。授权前必须展示：

- 将发送哪些资料。
- 服务方。
- 处理用途。
- 留存与训练承诺。
- 授权适用范围。

### 11.2 控制

- 支持单条、批量和明确规则授权。规则必须由用户主动创建或确认，AI 只能提出建议。
- AI 可自动升级保护等级。
- 降级、扩大用途或更换服务方需重新确认。
- 授权记录可查看和撤销。
- 所有外部处理记录模型、时间、用途、数据范围和费用。
- 敏感与严格敏感内容未经有效授权只能保存和手工编辑。

### 11.3 凭据与账号

用户不提供主账号密码。实施阶段由用户按引导创建自己名下的托管部署、数据库和 AI API 账号；系统通过受限密钥、环境变量或平台授权配置。凭据不得写入浏览器扩展、前端代码或 Git 仓库。

## 12. 成本控制

- 按任务选择模型，不让高价模型处理所有内容。
- OCR、去重和初筛优先使用合适的低成本能力。
- 展示每日、每月、模型和任务类型用量。
- 支持预算提醒和可配置上限。
- 批量处理前在可行时给出费用估算。
- 超出上限时暂停非关键 AI 任务，但不阻止原始资料采集。

## 13. 错误处理与恢复

- 幂等键避免重复提交。
- 内容指纹和外部标识避免重复资料和重复卡片。
- 后台任务自动重试并采用退避。
- 多次失败进入人工处理队列。
- 高峰期只要原始资料已保存，AI 任务可延后。
- 断网时扩展在本机暂存，并明确显示未同步状态。
- 页面结构变化时切换到选中文字、截图或手工上传。
- OCR 失败时保留原图并允许修正文本文。
- 通知失败不影响回顾生成，可重新发送。
- 检索索引损坏时可从原始资料和结构化知识重建。

## 14. 验收与测试

### 14.1 可调体验目标

- 支持入口的自动采集成功率达到 90% 以上；正式验收至少覆盖 30 次符合支持条件的真实采集尝试。
- 用真实模糊问题集测试，目标内容至少 90% 出现在搜索前五项；正式验收至少覆盖 20 个用户确认目标答案的问题。
- 每日确认默认先展示核心事项，通常可快速处理，但不设硬性时长。
- 每周回顾覆盖新增认知、重复问题、知识盲区、过时提醒和下一步建议。

自动采集成功率使用真实 ChatGPT 和小红书样本计算，分母只包含页面已加载、用户已登录、扩展拥有权限且页面类型在明确支持范围内的采集尝试。小红书正文读取失败但系统准确报告并通过截图或手工流程完成保存时，计入“兜底完成率”，不计入“自动采集成功率”，两项需分开报告。未达到最低样本量时可以报告阶段数据，但不能宣布正式通过该项验收。

### 14.2 不可降低的底线

- 服务器未确认原始资料保存时，不得显示采集成功。
- 部分采集和采集失败必须持续可见、可以重试。
- 高峰处理不得丢失已确认保存的原始资料。
- 知识库生成回答必须引用来源；没有证据则明确说明。
- 敏感数据未经对应授权不得发送给第三方 AI。
- 永久删除必须联动清理原文、附件和索引，并按引用关系删除或更新受影响卡片，不能留下失效引用。

### 14.3 测试范围

- 单元测试：去重、增量合并、敏感路由、授权范围、优先级和版本保护。
- 集成测试：采集到原始保存、后台处理、索引、问答引用、删除和恢复。
- 扩展端到端测试：Chrome、Edge、ChatGPT 页面和小红书成功/部分/失败路径。
- 压力与恢复测试：突发批量内容、队列积压、AI/OCR 超时和服务恢复。
- 检索评测：用户真实问题集，覆盖模糊表达、中英文术语和错别字。
- 隐私测试：越权访问、未授权外发、撤销授权和永久删除。
- 回顾质量测试：用户每周反馈“有用 / 一般 / 无用”。

## 15. Codex 交付里程碑

下列时间是 Codex 完成实现、测试与修复的保守项目区间，不是用户的开发任务。正式实施计划将按具体任务重新校准。

### 里程碑 A：可靠采集试用版

保守预计：3–7 个工作日。

- Web 基础、个人登录和数据隔离。
- 粘贴、文件和截图上传。
- ChatGPT 网页采集。
- 原始资料保存。
- 完整、部分、失败状态。
- 本地暂存和后台任务队列。

### 里程碑 B：搜得到、问得出

里程碑 A 后追加：5–10 个工作日。

- OCR、摘要和原子拆卡。
- 卡片编辑和版本保护。
- 混合搜索。
- 有引用的知识库问答。
- 小红书正文读取与截图兜底。

### 里程碑 C：知识成长闭环

里程碑 B 后追加：5–10 个工作日。

- 每日优先事项。
- 每周邮件回顾。
- 主题地图和知识关联。
- 轻量研究专题。
- 隐私、成本与审计界面。

### 里程碑 D：稳定与主动提醒

里程碑 C 后追加：5–10 个工作日。

- 真实样本评测和修复。
- Chrome/Edge 稳定性。
- 高峰压力和恢复测试。
- 在系统输入问题时提示相似历史。
- 完成首版验收。

连续推进且账号、授权和测试样本及时到位时，可靠采集试用版的参考区间为 3–7 个工作日，完整稳定首版的保守参考区间为 4–8 周。外部平台页面变化、第三方账号审核和反馈间隔会影响日历时间。

## 16. 职责划分

### 16.1 Codex 负责

- 架构、数据库、Web 应用和扩展实现。
- AI 处理、搜索、问答和回顾逻辑。
- 自动测试、浏览器验证和缺陷修复。
- 部署配置说明、隐私与成本控制。
- 各里程碑的可运行版本和验收记录。

### 16.2 用户参与

- 按引导注册自己名下的托管服务账号。
- 在浏览器安装并授权测试扩展。
- 每个里程碑提供少量真实使用样本。
- 确认采集、搜索与回顾是否符合习惯。
- 批准敏感资料的具体处理范围。

用户无需编写代码或自行维护传统服务器。

## 17. 已确认的关键决定

- 第一版选择 Web 应用 + Chrome/Edge 扩展。
- 主目标为自动或低摩擦采集，兼顾知识沉淀。
- 采集策略为自动暂存、AI 日常处理、用户快速确认和每周回顾。
- 保存完整会话与片段收藏两种模式。
- 首版从上线当天开始，不做历史迁移。
- 首版自动适配优先 ChatGPT 网页版和小红书网页版。
- 数据使用用户自己名下的托管服务账号，不要求传统服务器。
- 敏感数据可由合规第三方 AI API 临时处理，但需满足不用于训练、留存可控，并遵守分级授权。
- 首版个人使用，架构预留多用户。
- 首版包含轻量研究专题，不包含自动全网监控。
- 浏览器通知 + 每周邮件摘要。
- 中文为主，兼容英文资料。
- 成本以效果优先，但必须有明细、提醒和上限控制。
